# Affirm splinator: implementing the Subsampled Smooth Calibration Error

[Affirm/splinator#10](https://github.com/Affirm/splinator/issues/10) (open since 2026-01-01) asks for the Subsampled Smooth Calibration Error (SSCE) from Haghtalab, Qiao, Yang & Zhao (2024), "Truthfulness of Calibration Measures" ([arXiv:2407.13979](https://arxiv.org/abs/2407.13979)). The paper's claim is that standard calibration measures — ECE and its binned variants — are far from truthful: a forecaster can deliberately misreport and still score near-zero, while honest prediction can score badly. SSCE is the proposed remedy: under it, truthful prediction is optimal up to a constant factor.

I implemented the paper's definition: `smCE(x, p) = sup_{f ∈ F} Σ f(p_t)(x_t − p_t)` over 1-Lipschitz functions `[0,1] → [−1,1]`, and `SSCE(x, p) = E_S[smCE(x|_S, p|_S)]` — the expectation over uniform random subsets of the sequence. The PDF's typesetting of one equality in Definition 2.1 is garbled, so I cross-checked it against a secondary write-up.

The build splits in two. The supremum over an infinite function family is tractable: the objective only evaluates `f` at the sample predictions, so it reduces to choosing values `v_i = f(p_i)` with `|v_i − v_j| ≤ |p_i − p_j|` (after sorting, adjacent-pair constraints imply all pairs) and `|v_i| ≤ 1` — a linear program. Any LP-feasible values extend to an admissible function, so the LP optimum *equals* the true supremum; the inner problem is exact, not approximated. It's solved with `scipy.optimize.linprog`, already a core dependency. The exact `2^T` outer expectation is infeasible, so it's Monte Carlo with `random_state` for reproducibility.

The result is one new public function, `splinator.subsampled_smooth_calibration_error(labels, preds, n_draws=100, random_state=None)` in `src/splinator/metrics.py`, following the repo's docstring conventions. Three design decisions: the paper's output grows with sequence length, so I rescale to `[0, 1]` to sit alongside ECE, with the normalisation stated in the docstring; the LP beats a finite function grid, which only approximates the supremum; and the API is one function plus a private helper.

On a deliberately miscalibrated forecaster (constant 0.8 predictions against a true rate of 0.2), ECE scores 0.061 — it essentially misses it — while SSCE scores 0.613 (n=500, seed 123, 500 draws); a truthful calibrated forecaster scores SSCE 0.021 against ECE 0.055. The paper's point, demonstrated against this repo's own implementation. All 15 new unit tests pass — hand-checkable LP cases, known values, Monte Carlo-versus-exact-enumeration agreement on small T, seed reproducibility, edge cases — and the existing suite still passes (146 passed, 1 skipped, 1 xfailed; the one pre-existing failure is identical on the pristine checkout).

Honest limits: truthfulness is a theoretical claim about optimal forecasting strategies, cited from the paper rather than demonstrated empirically. The outer expectation is an estimate — `n_draws` trades accuracy for cost (~8ms per inner LP at n=500, so 500 draws run ~10s), and the 100-draw default is a starting point. The implementation follows the paper's binary-outcome setting (labels in {0,1}).
